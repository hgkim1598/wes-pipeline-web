# WES 진단 Agent 설명 개선 — A/B 비교 요약

## 실험 목적
같은 실제 WES 실행 결과를 설명할 때, 개선한 프롬프트·Knowledge가 초보자용 설명의 정확성과 읽기 쉬움을 바꾸는지 측정한다.

## 기존 방식(A)과 개선 방식(B)의 차이
- **프롬프트 공통 규칙 추가**
  - 경고 단계 수와 단계 이름을 쓰게 함
  - 수치의 뜻과 판단 기준 유무를 쓰게 함
  - 필드 이름 직역과 내부 설정 이름을 쓰지 않게 함
- **dbSNP Knowledge 수정**: 내부 이름 대신 화면에 보이는 산출물 이름을 안내함
- 숫자·근거 검증 gate는 A와 B가 같다.

## 비교 조건
- 같은 실제 Run 1개, 같은 모델 설정(Claude Sonnet), 같은 평가 코드
- A 3회, B 3회를 교차 실행 → 답변 확보는 A 2개, B 3개 (A 1회는 없는 근거 ID를 인용해 안전 검사가 거부함)
- 모든 답변을 같은 검사기 두 버전(v1·v2)으로 다시 채점

## 측정 결과 (답변 단위)

| 항목 | A | B |
|---|---|---|
| 경고 단계 수와 이름을 요약·주요 발견에 씀 | 0/2 | 3/3 |
| 평균 깊이의 뜻과 "기준이 없어 판단 불가"를 함께 씀 | 0/2 | 3/3 |
| 내부 설정 이름·서버 경로 노출 | 2/2 | 0/3 |
| 필수 용어 미설명 FAIL (v1 규칙, 답변당) | 8, 11 | 3, 1, 0 |
| 숫자·근거 결정론 평가 통과 | 2/3 실행 | 2/3 실행 |
| 평균 응답 시간 | 14.7초 | 15.8초 |

## 대표 문장
- **A:** "target 전체의 평균 깊이는 11.0116배이며, 평균이 0보다 커도 한 번도 읽히지 않은 위치가 있을 수 있습니다."
- **B:** "target 한 위치를 평균 몇 번 읽었는지를 나타내는 평균 깊이는 11.0116배입니다. 이 프로젝트에는 합격 기준이 없어 충분한지는 이 값으로 판단할 수 없습니다."
- **A:** "…resource bundle 검증 보고서(00_input_validation/resource_validation.txt)에서 dbsnp_vcf가 선언되지 않았다는 [NOTE] 항목을 보면 됩니다."
- **B:** "dbSNP 파일이 지정되지 않았다는 기록을 확인하려면, 실행 산출물 목록의 'Resource validation report'를 보세요."

## 한계
- 표본이 작다(답변 5개, 실제 Run 1개). 이 Run은 개발 중에 본 Run이다.
- 프롬프트와 Knowledge를 함께 바꿔서 어느 쪽 효과인지 나눌 수 없다.
- 검사기는 문자열 규칙이다. 새 답변은 아직 사람이 평가하지 않았다.
- "염기 단위" 같은 어려운 표현은 줄지 않았다. B 1회는 변이 후보 수 문장의 근거 인용이 빠져 평가 검사를 하나 실패했다.

## 상태 구분
- **구현 완료**: 개선 프롬프트·Knowledge, 검사기 v1·v2, A/B 비교 도구
- **평가 완료**: 이 Run에서 A 2개·B 3개 답변의 자동 검사
- **미완료**
  - 새 답변의 사람 평가 (블라인드 시트 준비됨)
  - 다른 Run에서의 검증
  - 프롬프트와 Knowledge 효과의 분리
