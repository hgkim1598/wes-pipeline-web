# 초보자 평가 기준 v2 (`beginner_v2`)

`beginner_v1`을 보완한 기준이다. v1 문서와 v1로 매긴 점수는 바꾸지 않는다.

- 대상 독자: **중학교 과학 수준의 배경지식이 있는 생물정보학 초보자.** DNA와 염기는 알지만
  시퀀싱 데이터, 정렬, 파이프라인 단계가 무엇을 만드는지는 모른다. 같은 설명을 연구자가
  읽어도 어색하지 않아야 한다.
- v1과 같이 사람 검토자가 답변과 근거를 읽고 판단하는 기준이다. 실제 사용자를 대상으로 한
  이해도 시험이 아니다. AI가 채점했다면 기록에 "AI 1차 검토"라고 적는다.
- 채점 값(`2` / `1` / `0` / `N/A` / `pending_review`), 답변 전체를 대상으로 한다는 규칙,
  점수마다 문장을 인용한다는 규칙, 한 문제는 한 항목에서만 감점한다는 규칙은 v1과 같다.

## v1과의 관계

| 항목 | v2에서 |
|---|---|
| B1 진행 상황 | v1과 같다 |
| B2 필수 전문용어 | **구체화** — 무엇을 "설명됨"으로 보는지, 개념 구분을 B2에서 분리 |
| B3 사실과 추론 구분 | v1과 같다 |
| B4 알 수 있는 것과 없는 것 | v1과 같다. B2에서 옮긴 개념 구분은 여기서 본다 |
| B5 다음 확인 사항 | **구체화** — 무엇을, 왜, 누가, 어디서 |
| B6 핵심 결론 우선 | v1과 같다 |
| H1, H2 | v1과 같다 |
| R1 문장 이해도 | **새 항목** |
| R2 문체 | **새 항목** |

### 기존 결과와 비교할 때

- v1 점수와 v2 점수는 **같은 척도로 직접 비교하지 않는다.** B2와 B5는 기준이 바뀌었고,
  R1·R2는 v1에 없다. 항목 이름이 같아도 v1의 B2 1점과 v2의 B2 1점은 같은 뜻이 아니다.
- 이전 답변과 비교하려면 이전 답변을 **v2로 다시 채점해 새 review 파일에** 기록한다.
  기존 review 파일의 v1 점수는 덮어쓰지 않는다.
- B1, B3, B4, B6, H1, H2는 기준이 같으므로 v1 결과와 나란히 볼 수 있다. 다만 같은 답변을
  다시 읽은 것이 아니면 검토자 차이가 섞인다.

## B2 필수 전문용어 설명 (v2)

**질문:** 사례의 핵심 사실을 전달하는 데 빠질 수 없는 용어를, 그 용어가 쓰인 자리에서
초보자가 이해할 수 있게 설명했는가?

**필수 용어:** 사례 spec의 `beginnerRubricV2.requiredTerms`에 미리 적는다. 각 항목은
`config/knowledge/wes_terms.json`의 term id를 가리킨다. 사례 spec에 없으면 `pending_review`다.

v1에서 필수 용어 목록에 섞여 있던 **개념 구분**(예: 염기 단위와 구간 단위, 필터 전 후보)은
용어가 아니다. B2에서 빼고 B4와 사례의 사람 검토 항목에서 본다.

**"설명됨"의 조건** — 다음 중 하나를 그 용어가 쓰인 **같은 문장** 또는 **같은 독립 항목**
(summary 하나, 또는 statement 하나) 안에서 충족한다.

1. 괄호 안의 한 줄 설명. 예: "read(시퀀싱으로 읽은 짧은 DNA 조각)"
2. 용어 없이 쉬운 말로 바꿔 씀. 예: "BAM" 대신 "정렬 파일"
3. 문장 자체가 뜻을 풀어 줌. 예: "한 위치가 몇 번 겹쳐 읽혔는지(깊이)는 평균 11.0116배입니다"

설명이 정확한지는 `wes_terms.json`의 `definition`과 `misreadings`를 기준으로 본다. 설명이
`misreadings`가 막는 뜻을 담으면 설명되지 않은 것으로 본다(사실 오류면 H1에서도 기록).

| 점수 | 기준 |
|---|---|
| 2 | 필수 용어가 쓰인 모든 항목에서 설명됐다 |
| 1 | 일부 항목에서만 설명됐다. **summary에서만 설명하고 다른 statement에서는 설명 없이 쓴 경우도 1점** |
| 0 | 필수 용어 대부분이 설명 없이 쓰였다 |

- 필수 용어를 답변에서 아예 쓰지 않고 같은 사실을 전달했다면 충족이다.
- 필수 용어가 아닌 용어(BAM, CIGAR, 도구 이름 등)는 B2에서 감점하지 않는다. 그 용어 때문에
  문장을 읽을 수 없으면 R1에서 본다.

**바꾼 이유:** Day 2 검토에서 "read를 summary에서만 설명한 경우"를 1점과 2점 중 어느 쪽으로
볼지 근거가 없었다. 화면은 statement를 하나씩 따로 보여 주므로 기준을 "쓰인 자리"로 정했다.

## B5 다음 확인 사항 (v2)

**질문:** 다음 확인 사항마다 **무엇을, 왜, 누가, 어디서** 확인하는지 초보자가 알 수 있는가?

| 요소 | 뜻 |
|---|---|
| 무엇 | 확인할 값이나 내용 |
| 왜 | 그 확인이 답하는 질문. 예: "어느 구간이 얼마나 덮였는지 알고 싶다면" |
| 누가 | 화면을 보는 사용자가 할 수 있는 일인가, 서버 관리자의 작업인가 |
| 어디서 | 사용자 작업이면 **웹 화면에서 찾을 수 있는 이름**(Files 화면의 산출물 이름 등). 관리자 작업이면 "서버 관리자가 하는 설정"이라고 밝히는 것으로 충분하다 |

| 점수 | 기준 |
|---|---|
| 2 | 사례 spec의 근거 있는 확인 사항마다 네 요소가 모두 드러난다 |
| 1 | 무엇과 왜는 있으나, 누가가 빠졌거나 위치가 도구 출력 이름처럼 전문가 표현이라 화면에서 찾기 어렵다 |
| 0 | 근거 있는 확인 사항을 제시하지 않았거나, 제시했지만 무엇을 보라는지 알 수 없다 |
| N/A | v1과 같다. 근거 데이터에 다음 확인 사항이 없고 답변도 지어내지 않았다 |

- 사용자는 서버 파일을 직접 열 수 없다. "resource_validation.txt에서"처럼 서버 경로만
  주는 것은 사용자 작업의 "어디서"로 인정하지 않는다.
- 근거 없는 확인 사항이나 조치를 지어낸 것은 v1과 같이 B3에서 감점한다.
- 이미 자동 보정된 항목에 확인 사항이 없는 것은 감점하지 않는다.

## R1 문장 이해도 (새 항목)

**질문:** 괄호 정의와 별개로, 문장 자체를 초보자가 한 번 읽고 이해할 수 있는가?

B2가 "낱말이 설명됐는가"를 본다면 R1은 "문장이 읽히는가"를 본다. 낱말이 모두 설명돼도
문장 구조 때문에 읽을 수 없으면 R1에서 감점한다.

**검토 방법:** statement마다 다음 순서로 읽는다.

1. **괄호를 지우고 읽는다.** 괄호 안 정의를 뺀 문장의 주어와 주장이 한 번에 드러나는가?
2. **새 개념의 수를 센다.** 한 문장에 독자가 처음 보는 개념이 셋 이상이면 표시한다.
3. **내부 표현을 찾는다.** knowledge나 데이터 구조의 표현이 그대로 옮겨졌는가?
   예: "결과 지점", "파이프라인 구조의 성질", "구간 수준 지표를 base 수준 사실로"
4. **오해 가능성을 본다.** 맥락 없이 따로 읽었을 때 실제와 다른 결론으로 읽히는가?
   예: 경고가 남은 실행에서 "검증 항목은 모두 통과했습니다"만 단독으로 쓰면 "문제 없음"으로 읽힌다.

| 점수 | 기준 |
|---|---|
| 2 | 모든 statement가 1–4에 걸리지 않는다 |
| 1 | 한두 문장이 걸린다 |
| 0 | 여러 문장이 걸려 답변 전체를 읽기 어렵다 |

- 점수와 함께 **가장 읽기 어려운 문장 하나**를 인용하고, 1–4 중 무엇에 걸렸는지 적는다.
- 문장이 길다는 것만으로는 감점하지 않는다. 길이와 숫자 개수는 v1의 A4처럼 참고 지표로 따로 적는다.

## R2 문체 (새 항목)

**질문:** 쉬운 말을 쓰면서도 객관적이고 차분한 설명문의 문체를 지켰는가?

쉬운 설명과 가벼운 문체는 다르다. **쉬운 말로 바꿔 쓰는 것은 감점하지 않는다.** 다음을 감점한다.

| 구분 | 예 |
|---|---|
| 구어체·말 걸기 | "~거든요", "~해 볼까요?", "걱정하지 않으셔도 됩니다" |
| 감탄·과장 | "다행히", "놀랍게도", "아주 중요한" |
| 과도한 비유 | 사실을 비유로 대신함. 짧은 보조 비유 하나는 허용 |
| 번역투·내부 지시 노출 | "독자가 직접 할 수 있는 작업이 아닙니다", "열어 보지 않았기 때문에" |
| 판단 어휘 | "안심해도 됩니다", "문제없습니다" (근거 없는 판정이면 B3·B4에서도 본다) |

| 점수 | 기준 |
|---|---|
| 2 | 위 표에 해당하는 표현이 없다 |
| 1 | 한두 표현이 있으나 전체는 객관적인 설명문이다 |
| 0 | 여러 표현이 있어 전체 문체가 가볍거나 어색하다 |

- 같은 표현이 여러 번 나오면 한 번으로 센다.
- 연구자가 읽어도 어색하지 않은지가 기준이다. 존댓말 평서문("~입니다", "~했습니다")은 감점하지 않는다.

## 기록 형식

review 파일의 `rubric.id`를 `beginner_v2`로 적고, 항목별 기록 형식은 v1과 같다
(`status`, `score`, `rationale`). R1에는 `hardestStatement`, R2에는 `flaggedExpressions`를
함께 적을 수 있다. v1으로 채점한 기록과 v2로 채점한 기록은 한 review 파일에 섞지 않는다.
