# 설명 품질 검사기 — 사람 검토지 v1 (검사기 판정 가림)

이 문서에는 **검사기의 판정이 없습니다.** 판정과 근거는 `answer_key.md`에 따로 있습니다.
검토를 마칠 때까지 `answer_key.md`를 열지 마세요. 먼저 보면 판단이 검사기 쪽으로 기울 수 있습니다.

## 이 자료의 성격

- 실제 모델 답변 18개 사례와 합성 사례 2개입니다. 합성 사례는 제목에 **[synthetic]** 이라고 적었습니다.
  합성 문장은 사람이 만든 검사용 문장이며 실제 모델 출력이 아닙니다.
- 실제 답변은 저장된 baseline 파일에서 그대로 옮겼습니다. 원문은 고치지 않았습니다.
- **모든 실제 답변은 개발 데이터입니다.** 검사 규칙을 만들거나 고칠 때 이미 본 답변이므로,
  이 검토 결과는 '개발 데이터에서 검사기가 맞게 판단했는가'를 보여줄 뿐 새 답변에서의 성능을 보여주지 않습니다.
- 독자 기준: 중학교 과학 수준의 배경지식이 있는 생물정보학 초보자(`rubric/beginner_v2.md`).

## 판정 방법

각 사례마다 질문에 **정상 / 오류 / 애매함** 중 하나를 고르고, 필요하면 한 줄 메모를 남깁니다.
결과는 `responses.json`의 해당 사례 칸에 적습니다(`"정상"`, `"오류"`, `"애매함"`).

| 선택 | 언제 고르나 |
|---|---|
| 정상 | 질문이 묻는 조건이 충족됐다고 판단할 때 |
| 오류 | 충족되지 않았다고 판단할 때 |
| 애매함 | 어느 쪽인지 정하기 어렵거나, 판단에 필요한 정보가 부족할 때. 이유를 메모에 적어 주세요 |

### 용어 사례 — 질문 두 개

- **Q1 이 항목만 보고:** 화면에 이 문장(항목) 하나만 보인다고 할 때, 독자가 그 용어의 뜻을 알 수 있는가?
  용어를 쓰지 않고 쉬운 말로 같은 뜻을 전했다면 정상입니다. 설명이 있어도 뜻이 틀렸다면 오류입니다.
- **Q2 답변 전체에서:** 같은 답변의 어느 항목에서든 그 용어가 맞게 설명되어 있는가?
  ('같은 답변의 관련 항목'을 참고하세요.) 합성 사례는 문장이 하나뿐이라 Q2가 없습니다.
- 설명이 맞는지는 함께 적은 '기준 자료'(`config/knowledge/wes_terms.json`)와 비교합니다.

### 내부 표현 사례

- **Q:** 이 문장에 초보자가 이해할 수 없는 내부 구현 정보가 설명 없이 드러나 있는가?
  예: 서버 설정 이름, 서버 파일 경로, 내부 단계 ID, 코드 값, 번역하지 않은 영어 원문 표기, 데이터 필드 이름을 그대로 옮긴 말.
- **정상 = 없다, 오류 = 있다.** 오류라면 어떤 표현인지 `expressions`에 적어 주세요.
- 도구 이름처럼 연구자에게 필요할 수 있는 표현은 판단이 갈릴 수 있습니다. 그때는 애매함과 메모를 남겨 주세요.

### Run 사실 사례

- **Q:** 답변 전체(부록)를 읽은 독자가 질문의 사실을 알 수 있는가? 함께 적은 '실행 기록' 기준입니다.

### 표시

- 🔎 **전문 지식 필요**: 설명의 정확성을 판단하려면 용어 지식이 필요합니다. 기준 자료를 꼭 확인하세요.
- 📄 **원문·화면 확인 필요**: 웹 화면이나 원문에서 무엇을 볼 수 있는지 확인해야 판단할 수 있습니다.
